## Guidelines

- 崇尚 Unix 哲学：小巧、可组合、显式、朴素。
- 设计方案时，从第一性原理推导：明确目标、约束和已知事实，推导满足当前需求的最简单方案，并为各要素设定预估代码量作为软目标；不新增无实际需求依据的抽象
 、配置项或间接层，明显超出预估时先停下来检查是否过度实现。
- 编写代码时，只实现能够正确满足需求的最小改动；不要为未经请求或假设性场景增加防御性代码。扩大改动范围前先询问用户。
- 不以维护向后兼容性为目标：直接删除或替换废弃路径，不添加兼容层；确需兼容时先询问用户。
- 实现功能或新增依赖前，先检查项目现有依赖的文档与类型定义；仅当成熟依赖能降低整体复杂度或提高可靠性时再引入。
- 每一行代码都必须有存在的价值，可读性优先于炫技。
- 代码应包含中文注释，注释风格与详细程度参照 pi 源码。
- 搜索文本时使用 `rg`，不要使用 `grep`。
- 多个工具调用彼此独立时，应尽可能并行执行。
- 无既定视觉规范时，UI 默认采用 Nord 风格：https://github.com/nordtheme/nord
- 回复应简洁但信息充分；除工具调用和代码生成外，尽量控制在 1～4 句话以内。

## Project memory

项目中的 AGENTS.md 是项目记忆。当稳定事实、决策、命令、状态、注意事项或工作流程发生变化时，更新作用域内最近的 AGENTS.md。

## 工作方法论

- 动手前明确任务目标、完成标准和非目标；每项行动都必须能说明它如何推进完成标准。
- 把问题拆解成最小、可端到端验证的垂直切片，逐个完成。
- 发现旁支时，仅在其阻塞当前目标时处理；否则记录并立即回到主线。每完成一个垂直切片，重新核对目标和剩余工作。
- 每个决定都必须能够说明“为什么”，而不只是“怎么做”。
